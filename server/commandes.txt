Voici le récapitulatif exact du comportement actuellement implémenté :

Table service_person reçoit une nouvelle ligne dans exactement 4 cas :

1. Création d'un personnel (formulaire "Ajouter")
Si le champ Date prise de service est rempli → insertion d'une ligne :
type = "prise"
date_service = la date saisie
motif = "" (vide)
Si le champ est laissé vide → aucune ligne n'est créée.
2. Modification d'un personnel (formulaire "Modifier")
Le champ Date prise de service n'est visible en modification que si il était vide avant.
S'il était vide et qu'on le renseigne maintenant → insertion d'une ligne type = "prise", date_service = date saisie, motif = "".
S'il était déjà renseigné avant → le champ est caché, donc rien n'est modifié et aucune ligne n'est créée.
3. Bouton "Fin service" (uniquement visible si le personnel est actif)
Ouvre le modal → l'utilisateur saisit une date et un motif obligatoires.
À l'enregistrement :
insertion d'une ligne type = "arret", date_service = date saisie, motif = motif saisi
etat du personnel passe à false (inactif)
4. Bouton "Reprise service" (uniquement visible si le personnel est inactif)
Ouvre le même modal (libellés adaptés) → date et motif obligatoires.
À l'enregistrement :
insertion d'une ligne type = "prise", date_service = date saisie, motif = motif saisi
etat du personnel passe à true (actif)
Résumé type :

"prise" → soit automatique (création/1ère modif avec la date de prise de service, motif vide), soit manuelle via "Reprise service" (avec motif).
"arret" → uniquement via "Fin service" (avec motif obligatoire).

-- ===== Initialisation du stock sachets à partir des ventes déjà existantes =====
-- À exécuter UNE SEULE FOIS, juste après la création des 2 tables ci-dessus et
-- avant de commencer à utiliser le module (sinon les quantités seront comptées
-- deux fois). Système en place depuis plus d'un an : on reconstitue l'historique
-- mois par mois plutôt qu'en un seul bloc — une ligne par mois calendaire, datée
-- au 1er du mois concerné.
-- Sortie = somme des ventes du mois (table `ventes`).
-- Entrée = somme des ventes annulées du mois (table `ventes_annuler`), en restitution.

INSERT INTO `stock_sachet_sorties` (`quantite`, `date_sortie`, `motif`, `id_vente`, `createdBy`, `createdAt`, `updatedAt`)
SELECT
  SUM(`quantite`),
  STR_TO_DATE(CONCAT(YEAR(`date_vente`), '-', MONTH(`date_vente`), '-01'), '%Y-%m-%d'),
  CONCAT('Initialisation - ventes de ', DATE_FORMAT(`date_vente`, '%m/%Y')),
  NULL,
  'system',
  NOW(),
  NOW()
FROM `ventes`
GROUP BY YEAR(`date_vente`), MONTH(`date_vente`);

INSERT INTO `stock_sachet_entrees` (`quantite`, `date_production`, `observation`, `createdBy`, `createdAt`, `updatedAt`)
SELECT
  SUM(`quantite`),
  STR_TO_DATE(CONCAT(YEAR(`date_vente`), '-', MONTH(`date_vente`), '-01'), '%Y-%m-%d'),
  CONCAT('Initialisation - restitution ventes annulées de ', DATE_FORMAT(`date_vente`, '%m/%Y')),
  'system',
  NOW(),
  NOW()
FROM `ventes_annuler`
GROUP BY YEAR(`date_vente`), MONTH(`date_vente`);


-- ===== Régularisation : ramener le stock exactement à 0 =====
-- Les scripts ci-dessus enregistrent des SORTIES historiques (les ventes) et déjà
-- un peu d'ENTRÉE (restitution des ventes annulées) -> stock encore négatif.
-- Pour tomber pile à 0, chaque entrée de régularisation ne compense QUE la
-- différence (sortie du mois − restitution déjà enregistrée ce même mois), pas
-- toute la sortie : sortie_mois = entrée_restitution_mois + entrée_régularisation_mois.
-- Le WHERE/JOIN ne touche que les lignes créées par les scripts d'initialisation
-- ci-dessus (jamais les vraies sorties/entrées enregistrées depuis la mise en service).

INSERT INTO `stock_sachet_entrees` (`quantite`, `date_production`, `observation`, `createdBy`, `createdAt`, `updatedAt`)
SELECT
  s.`quantite` - COALESCE(r.`quantite`, 0),
  DATE_ADD(s.`date_sortie`, INTERVAL 1 DAY),
  CONCAT('Régularisation stock - production non enregistrée de ', DATE_FORMAT(s.`date_sortie`, '%m/%Y')),
  'system',
  NOW(),
  NOW()
FROM `stock_sachet_sorties` s
LEFT JOIN `stock_sachet_entrees` r
  ON r.`date_production` = s.`date_sortie`
  AND r.`observation` LIKE 'Initialisation - restitution%'
WHERE s.`motif` LIKE 'Initialisation - ventes de%'
  AND (s.`quantite` - COALESCE(r.`quantite`, 0)) > 0;
